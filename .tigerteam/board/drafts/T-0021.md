## Goal
User report: in full screen, the small floating toolbar revealed at the top
edge hides again so quickly it is impossible to actually click. Diagnose on
a live fullscreen session and FIX it: the toolbar must stay visible for as
long as the pointer is over it (plus a grace period after leaving), on
macOS, without changing Linux behavior.

## Context
- The widget is `src/virt-viewer-timed-revealer.c` (GtkRevealer driven by an
  unreveal timer + pointer enter/leave). Upstream recently touched the timer
  logic ("Don't schedule unreveal timer if not active", commit 9f3b839) —
  read it before assuming the bug is ours.
- Prime suspect on quartz: enter-notify/leave-notify crossing events are
  unreliable (spurious leave events, or events not delivered through the
  overlay stack), so the unreveal timer fires while the pointer is still
  over the toolbar. Instrument the crossing events to confirm before
  fixing. A motion-based keep-alive (reset the timer on motion within the
  revealer) or a quartz-guarded longer grace period are acceptable fix
  shapes; pick based on what the instrumentation shows and justify.
- Test against a live connected session (same recipe as T-0020: qemu
  `-vnc 127.0.0.1:1` target; the bundle's launcher with
  `vnc://127.0.0.1:5901`). T-0020's report may already carry relevant
  fullscreen findings — read it in done/ first.
