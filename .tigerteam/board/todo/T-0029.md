## Goal
Extend T-0025's keyboard capture to the chords macOS swallows before the
app ever sees them — ⌘-Space, ⌘-Tab, ⌘`, screenshot keys — using a
CGEventTap, so a Hyprland guest bound on SUPER is fully usable. This is
the standard mechanism for this app category (Parallels, VMware Fusion,
Screen Sharing all do it); it requires a one-time Accessibility grant.

## Context
- Read `macos-native/README.md`; T-0025's report in `.tigerteam/board/done/`.
- Locked design (PM):
  - `CGEventTapCreate(kCGSessionEventTap, kCGHeadInsertEventTap,
    kCGEventTapOptionDefault, keyDown|keyUp|flagsChanged mask, …)` on the
    main thread's runloop. In the callback: if capture is ON **and** the
    viewer window is key **and** a session is connected → consume the
    event (return NULL) and forward it through the existing scancode path
    (`CGEventGetIntegerValueField(kCGKeyboardEventKeycode)` is the same
    keycode space as `NSEvent.keyCode`; reuse the keymap + flagsChanged
    synthesis). Otherwise return the event untouched so the rest of the
    system behaves normally. Handle `kCGEventTapDisabledByTimeout` /
    `…ByUserInput` by re-enabling the tap.
  - **Single source rule**: while the tap is installed and enabled, it is
    the ONLY keyboard sender — guard the `VsmView` responder methods
    (keyDown/keyUp/flagsChanged/performKeyEquivalent) with a flag so no
    chord is sent twice. When the tap is unavailable (no Accessibility
    grant), everything falls back to exactly T-0025's behavior.
  - **⌘Q policy (user decision 2026-09-01, mirrors Chrome's hold-to-quit
    + UTM's captured-goes-to-guest):** while capture is active, a TAP of
    ⌘Q is forwarded to the guest like any other chord (Omarchy SUPER+Q =
    close window, used constantly); HOLDING ⌘Q for ~1 s quits the viewer
    — implement with a keyDown-starts / keyUp-cancels timer and show a
    brief "Hold ⌘Q to Quit" overlay (a borderless HUD-style panel or
    NSTextField overlay is fine) while the key is down. On hold-quit,
    send the guest a release for the forwarded press first (no stuck
    Super/Q). When capture is off (or no session / window not key),
    plain ⌘Q quits immediately as today — T-0024's quit monitor keeps
    that role; rework it so both behaviors come from one place instead
    of racing.
  - **Escape chord: ⌃⌥ pressed together then released** (matches the
    T-0027 mouse-ungrab convention) toggles capture OFF from the
    keyboard. It is always handled locally, never forwarded; on toggle,
    release-all-keys to the guest so no modifier sticks. Capture also
    auto-suspends (tap passes everything through) when the window
    resigns key, the app deactivates, or the session disconnects.
  - **Permission flow**: on first enable call
    `AXIsProcessTrustedWithOptions` with the prompt option; if not
    trusted, degrade silently to T-0025 behavior and reflect it in the
    Input menu (e.g. "Capture System Shortcuts (needs Accessibility)"
    disabled-state or suffix), re-checking on each toggle. Never crash,
    never busy-poll TCC.
  - TCC attributes the grant to the responsible process — for a binary
    launched from a shell that is the terminal app, and after T-0026 it
    will be the `.app` (fresh grant then; note this in the README).
- **TCC reality check for your run**: the supervisor's Terminal likely
  has NO Accessibility grant (only Screen Recording). Trigger the prompt
  once, then test `AXIsProcessTrusted()`. If the grant is not present,
  DO NOT wait or retry-loop: implement everything, verify the degraded
  path + pass-through behavior live, verify the capture path as far as
  possible (tap installs, callback sees events, single-source guard) and
  put the exact System Settings steps for the user in your report — the
  PM/user does the final ⌘-Space live check. Do not modify TCC databases
  or use `tccutil`/private APIs.
- Live target `spice://100.101.77.113:5900` (disposable Omarchy VM; user
  allows unlocking + clicking around). Lock-screen password: root `.env`
  `GUEST_UNLOCK_PW` — type it via the viewer to unlock; never echo it
  into reports/logs/commits. No destructive/power chords.
- Engine ceiling ≈45 min: commit early and often; hand off INCOMPLETE
  with precise next steps rather than pushing through.
