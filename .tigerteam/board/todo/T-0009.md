## Goal
Prove the packaged app actually runs as a macOS GUI app and record the
evidence. This ticket produces a report and screenshots; the only allowed
code change is a "Known issues" list in `docs/macos.md`.

## Context
- You run UNSANDBOXED with access to WindowServer. Steps:
  1. `bash build-aux/macos/check.sh && bash build-aux/macos/make-bundle.sh`
  2. `mkdir -p build/qa`; `open "build/Remote Viewer.app"`; wait 5 s;
     `screencapture -x build/qa/T-0009-launch.png` — the connect dialog must
     be visible.
  3. Verify the macOS menu bar shows the app's menus (T-0005):
     screenshot `build/qa/T-0009-menubar.png`.
  4. In the connect dialog, enter `spice://127.0.0.1:1` and connect;
     screenshot the resulting error dialog `build/qa/T-0009-error.png`.
  5. Quit via ⌘Q; confirm the process exited (`pgrep -f 'Remote Viewer' ||
     echo gone`).
  6. Run the bundle on a "clean" environment:
     `env -i PATH=/usr/bin:/bin HOME=$HOME "build/Remote Viewer.app/Contents/MacOS/remote-viewer-launcher" --version`
     (or the actual CFBundleExecutable) prints the version — proves no
     Homebrew env leaks.
  7. `log show --last 2m --predicate 'process == "remote-viewer"' | grep -iE 'error|warn' | head -20`
     → summarize anything alarming.
- Write findings to `build/qa/T-0009-report.txt` AND into the Worker report.
  Every defect found becomes a bullet in `docs/macos.md` "Known issues";
  do not fix anything else here.
- Always `pkill -f 'Remote Viewer.app'` before finishing.
