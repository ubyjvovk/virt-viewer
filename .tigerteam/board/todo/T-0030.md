## Goal
Fix a protocol violation found in PM live testing: when the guest
requests clipboard text we advertised and the pasteboard has no
(non-empty) string, `vsm-clipboard.m` logs "host has none" and returns
WITHOUT answering. The agent protocol expects an explicit empty/NONE
notify; a dangling request can wedge the guest agent's clipboard state
machine (observed: after one unanswered request, the guest ignored all
later grabs). Also stop offering when there is nothing to offer.

## Context
- The defect: `macos-native/vsm-clipboard.m` ~line 172 — the
  `!text.length` branch bare-returns. Reference behavior: spice-gtk's
  `src/spice-gtk-session.c` answers an unfulfillable request with
  `spice_main_channel_clipboard_selection_notify(main, selection,
  VD_AGENT_CLIPBOARD_NONE, NULL, 0)` — verify the exact call/enum in the
  unpacked spice-gtk 0.42 source (path in T-0023's Context, done/).
- Locked fixes (PM):
  1. Add a "no data" answer: extend `vsm-spice.h/.c` with a send op
     (e.g. `vsm_spice_clipboard_send_none()`) following the existing
     GLib-thread marshalling pattern, and call it from the empty branch
     so EVERY guest request gets exactly one answer.
  2. Don't advertise what we don't have: the poller (first poll
     included) must offer only when the pasteboard has a NON-EMPTY
     string. An empty pbcopy item must produce no grab. The
     offer→request→cleared race is then covered by fix 1.
  3. Trace lines for both (lengths only, never contents).
- Live target `spice://100.101.77.113:5900` (disposable Omarchy VM,
  benign input only). The guest's `spice-vdagent` is flaky today (user
  is restarting it repeatedly; it also crashes on data install — a
  separate guest-side bug, out of scope). If the agent is up:
  reproduce the PM's A/B — connect with an EMPTY host pasteboard
  (`pbcopy </dev/null`), see the guest request, verify the NONE answer
  goes out (SPICE_DEBUG/VSM_TRACE), then `pbcopy` a marker and confirm
  the guest still requests the new offer (agent not wedged). If the
  agent is down/crashed, evidence degrades to: trace showing no offer
  on empty pasteboard + code inspection of the NONE path + the
  spice-gtk parallel cited; say so plainly.
- The viewer's pasteboard poller runs only while the app is ACTIVE —
  activate the window (osascript is granted) or the offer never fires.
- Engine ceiling ≈45 min; commit early; INCOMPLETE handoff over
