## Review areas — examine every one; give a one-line per-area result even
when clean
1. C code (`src/virt-viewer-macos.[ch]`, `src/remote-viewer.c`,
   `src/virt-viewer-util.c`, `src/virt-viewer-window.c`,
   `src/virt-viewer-app.c`): memory (leaks, CFRelease/g_free pairing,
   ref-count of GMenu/GtkBuilder objects), GLib/GTK idiom, NULL and error
   paths, lifecycle (init/dispose ordering).
2. Platform guards: does any change alter behavior on Linux or Windows?
   (hotkey table entries and lookup order, widened accel masks in
   `accel_key_to_keys()`, XDG/GSettings env seeding, meson flag changes).
3. Build system (`meson.build`, `meson_options.txt`, `src/meson.build`,
   `config.h.in`): option/dependency plumbing, behavior when
   gtk-mac-integration is absent, non-darwin configure paths.
4. Shell (`build-aux/macos/make-bundle.sh`, `make-dmg.sh`, `check.sh`):
   quoting, error paths under `set -euo pipefail`, temp-file hygiene,
   the sign-after-rewrite ordering claim, relocatability assumptions.
5. Packaging metadata (`build-aux/macos/Info.plist.in`,
   `build-aux/macos/virt-viewer.rb`): URL scheme + document-type
   declarations, formula correctness.
6. Hotkeys: cmd/meta mapping semantics (`ctrl_key_to_gtk_key`,
   `accel_key_to_keys`), man-page claims vs code
   (`man/remote-viewer.pod`, `man/virt-viewer.pod`),
   `tests/test-hotkeys.c` coverage of the new names.
7. Series quality, per commit: does each commit message's claim match its
   content; is anything in the wrong commit; does the series look
   bisectable (no commit obviously referencing code introduced later)?
8. Docs accuracy: `docs/macos.md` and `README.md` vs the code as landed.
