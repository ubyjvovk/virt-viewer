## Goal
Turn the PoC into an app a person can launch without a terminal: started
with no URI it shows a connect window; an auth failure prompts for a
password; a connection error or disconnect shows an alert with
Reconnect/Close instead of silently exiting. With a URI on argv, behavior
is unchanged (connect immediately).

## Context
- Read `macos-native/README.md`; T-0022/T-0023 reports in
  `.tigerteam/board/done/`.
- Locked UX decisions (PM):
  - **Connect window** (no argv URI): a small window with a URI text field
    (pre-filled from `NSUserDefaults` key `VsmLastURI`), a default
    "Connect" button (Return activates). On connect: save the URI to
    defaults, hide the connect window, proceed exactly as the argv path.
  - **Auth**: when the session fails with `SPICE_CHANNEL_ERROR_AUTH`,
    show an `NSAlert` with an `NSSecureTextField` accessory ("Password
    for <uri>"), then retry. Retry = tear down and recreate the session
    (`vsm_spice_stop`/`free`, `new`, `start`) — add
    `void vsm_spice_set_password(VsmSpice *self, const char *password)`
    (callable only before `start`; sets the session's `password` property
    on the GLib thread at start). Keep the password in process memory
    only — never in NSUserDefaults, logs, or trace output.
  - **Errors/disconnect**: route the existing `disconnected(reason)`
    callback to an `NSAlert` showing the reason, buttons **Reconnect**
    (recreate the session with the same URI + any password entered this
    run) and **Close** (return to the connect window; the app keeps
    running). ⌘Q always quits. To distinguish auth failure from generic
    failure, extend the disconnect path with an error kind — simplest:
    change the callback to `disconnected(void *user, const char *reason,
    int auth_failed)` or add a getter; your call, keep it minimal, adjust
    all callers.
  - File layout: putting the connect window + alerts in a new
    `macos-native/vsm-connect.m` (or folding into `main.m` if small) is
    your call; keep `main.m` readable.
- The channel-error signal carrying `SPICE_CHANNEL_ERROR_AUTH` is on
  `SpiceChannel` (`channel-event` with `SPICE_CHANNEL_ERROR_AUTH`); see
  spice-gtk 0.42 source (path in T-0023) — `spice-channel.h`,
  and spice-gtk's own `spice_session` usage.
- Test target `spice://100.101.77.113:5900` (unauthenticated, disposable,
  benign input only). Evidence paths:
  - connect window flow: launch with no args, type the URI, connect —
    screenshots.
  - error alert: `spice://127.0.0.1:1` → alert appears with a real error
    reason; Reconnect retries (fails again); Close returns to the connect
    window; app does not exit.
  - auth prompt: the target has no password, so force the auth path once
    with a LOCAL, uncommitted hack (e.g. temporarily map a generic error
    to auth, or run a password-protected local test if you can trivially
    make one); screenshot the prompt and state in the report exactly how
    it was triggered. Committed code must contain no fake-auth switch.
- Engine ceiling ≈45 min wall: commit early and often; hand off
  INCOMPLETE with precise next steps rather than pushing through.
