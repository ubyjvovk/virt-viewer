## Goal
Make `--hotkeys` usable with the Command key on macOS and document how the
default Ctrl+Alt combos map on a Mac keyboard.

## Context
- Hotkey strings are parsed in `src/virt-viewer-app.c` (grep
  `virt_viewer_app_set_hotkeys` / `virt_viewer_app_set_hotkey`). Tokens like
  `ctrl`, `alt`, `shift`, `super` (check which are accepted) are converted to
  a GTK accelerator string such as `<Control><Alt>f`.
- Add `cmd` and `meta` as synonyms producing `<Meta>` (GDK on quartz maps
  the Command key to `GDK_META_MASK`). Keep everything else identical.
- `tests/test-hotkeys.c` already tests parsing — add cases:
  `release-cursor=cmd+alt+r` → contains `<Meta><Alt>r` (or whatever the
  existing test asserts on — follow its pattern), `meta+q`, and that an
  unknown modifier still errors.
- Man pages: `man/virt-viewer.pod` and `man/remote-viewer.pod` `--hotkeys`
  section (grep `hotkeys`): add `cmd`/`meta` to the accepted modifiers and a
  one-line macOS note (Command key = `cmd`; Option = `alt`).
- BUG to fix (observed on the host, 2026-08-30): running `build/src/remote-viewer`
  on macOS logs `virt-viewer-WARNING (../src/virt-viewer-window.c:834):
  accel_key_to_keys: runtime check failed: ((accel_mods & ~(GDK_SHIFT_MASK |
  GDK_CONTROL_MASK | GDK_MOD1_MASK)) == 0)` — quartz hands the send-key
  menu an accelerator carrying `GDK_META_MASK` (⌘). Extend the `modifiers[]`
  table in `accel_key_to_keys()` with `{GDK_META_MASK, GDK_KEY_Meta_L}` and
  `{GDK_SUPER_MASK, GDK_KEY_Super_L}`, widen the `g_warn_if_fail` mask and
  the allocation (`G_N_ELEMENTS(modifiers) + 2` already scales) accordingly.
  This is platform-neutral and safe on Linux too.
- `docs/macos.md` "Keyboard" section: default hotkeys on macOS, how to send
  Ctrl+Alt+Del via the menu, that `cmd+...` hotkeys never reach the guest.
