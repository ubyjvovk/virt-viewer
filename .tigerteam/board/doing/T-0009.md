### Findings, severity order

1. **P1 — module caches use CWD-relative paths.**
   `Contents/Resources/lib/gdk-pixbuf-2.0/2.10.0/loaders.cache` and
   `.../lib/gtk-3.0/3.0.0/immodules.cache` list `"loaders/libpixbufloader_svg.so"`
   / `"immodules/im-quartz.so"`. gdk-pixbuf and GTK resolve those against the
   process CWD, not the cache directory, so no module ever loads. Created on
   purpose by `relativize_cache` at `build-aux/macos/make-bundle.sh:160-174`.
   `GDK_PIXBUF_MODULEDIR` does not fix it (verified) — it only affects cache
   generation.
2. **P1 — duplicate `LC_RPATH` on `libpixbufloader_svg.so`.**
   `otool -l ".../loaders/libpixbufloader_svg.so" | grep -A2 LC_RPATH` lists
   `@executable_path/../Resources/lib/` twice and dyld refuses the load with
   `duplicate LC_RPATH`, so even an absolute cache path fails. It is the only
   affected module (all 10 pixbuf loaders + 9 immodules were checked).
   (1)+(2) together are what crash the app: GTK uses `g_assert()` in
   `ensure_surface_for_gicon()` (`gtk/gtkiconhelper.c:495`), so a failed icon
   load aborts the process. Faulting stack, identical in all three crash
   reports `~/Library/Logs/DiagnosticReports/remote-viewer-2026-08-30-{153037,153130,153249}.ips`:
   `abort < g_assertion_message_error < ensure_surface_for_gicon <
   gtk_icon_helper_load_surface < _gtk_icon_helper_draw < gtk_entry_draw`.
3. **P1 — ⌘Q and the Quit menu items are dead.** With the app verified
   frontmost, ⌘Q does nothing; the menu item is disabled
   (`AXEnabled` of *Quit Remote Viewer* and *Quit and Close All Windows* =
   `false`). Escape and the window close button do not terminate it either, so
   there is no GUI route out of the app.
4. **P2 — no native input method**: `im-quartz.so` never loads (consequence of
   finding 1); stderr shows `Loading IM context type 'quartz' failed` on every
   launch.
5. **P3 — Homebrew path leak**: `immodules.cache` entries still carry
   `/opt/homebrew/Cellar/gtk+3/3.24.52/share/locale`.
6. **P3 — non-native window chrome**: the main viewer window keeps the GTK
   client-side header bar with its own minimise/maximise/close buttons and no
   macOS traffic lights (see `T-0009-error-recovered.png`).
7. **P3 — no accessibility tree for GTK content**: only the title bar buttons
   are exposed to the macOS AX API, so VoiceOver and AX automation cannot
   reach dialog contents.
