## Goal
A script `build-aux/macos/make-bundle.sh` that turns a finished meson build
into a self-contained, relocatable, ad-hoc-signed `Remote Viewer.app` that
runs on a Mac without Homebrew installed.

## Context
- Inputs: an existing build dir (default `build`, override `BUILD_DIR`),
  output `$BUILD_DIR/Remote Viewer.app` (override `APP_DIR`).
- Approach (PM decision — follow it):
  1. `DESTDIR=<tmp> meson install -C $BUILD_DIR` (prefix is whatever meson
     was configured with; read it via `meson introspect --buildoptions`).
  2. Layout: `Contents/MacOS/remote-viewer` (the real binary, plus
     `virt-viewer` next to it), `Contents/Resources/share/{locale,icons/hicolor,
     mime}` copied from the DESTDIR install, `Contents/Resources/lib/` for
     dylibs, `Contents/Info.plist`, `Contents/Resources/remote-viewer.icns`,
     `Contents/PkgInfo` (`APPL????`).
  3. Runtime data GTK needs that meson does not install — copy from
     `$(brew --prefix)`: `share/glib-2.0/schemas` (then run
     `glib-compile-schemas` on the copy), `share/icons/Adwaita` (only the
     `16x16 22x22 24x24 32x32 48x48 scalable symbolic` subtrees + index.theme
     — keep the bundle < 150 MB), `lib/gdk-pixbuf-2.0/2.10.0/loaders/*.so`
     + regenerate `loaders.cache` with `gdk-pixbuf-query-loaders` into
     `Contents/Resources/lib/gdk-pixbuf-2.0/2.10.0/loaders.cache` using
     bundle-relative paths, `lib/gtk-3.0/3.0.0/immodules` (+ `immodules.cache`),
     `share/mime` (run `update-mime-database` on the copy), GStreamer plugins
     are NOT bundled (audio is out of scope; note it in the doc).
  4. `dylibbundler -od -b -x Contents/MacOS/remote-viewer -x Contents/MacOS/virt-viewer
     -d Contents/Resources/lib/ -p @executable_path/../Resources/lib/`
     then run dylibbundler again over every bundled `.so` loader so their deps
     are also inside the bundle. Verify with `otool -L` (recursively) that no
     path starts with `/opt/homebrew` or `/usr/local`.
  5. Environment is NOT set by a shell launcher. T-0002 makes the binary
     detect the bundle and set `XDG_DATA_DIRS`/`GSETTINGS_SCHEMA_DIR` itself.
     The pixbuf/immodule caches are found via `GDK_PIXBUF_MODULE_FILE` and
     `GTK_IM_MODULE_FILE` — set those in `Info.plist` `LSEnvironment`
     using `@executable_path`-free ABSOLUTE paths is impossible for a
     relocatable app, so instead: the script rewrites the caches with
     relative entries and the T-0002 helper is extended in THIS ticket only
     if strictly necessary — prefer `Info.plist` `LSEnvironment` with
     `GDK_PIXBUF_MODULE_FILE=../Resources/lib/gdk-pixbuf-2.0/2.10.0/loaders.cache`
     resolved relative to cwd is NOT reliable; the accepted solution is a
     tiny launcher `Contents/MacOS/remote-viewer-launcher` (bash, `set -eu`,
     computes `$(dirname "$0")/../Resources`, exports the two vars, `exec`s
     the binary) and `CFBundleExecutable` = the launcher. Document why.
  6. `Info.plist` from `build-aux/macos/Info.plist.in` with `@VERSION@`
     substituted (read the version from `meson introspect --projectinfo`):
     CFBundleIdentifier `org.virt-manager.remote-viewer`, CFBundleName
     "Remote Viewer", CFBundleExecutable, CFBundleIconFile, CFBundlePackageType
     APPL, LSMinimumSystemVersion 12.0, NSHighResolutionCapable true,
     NSSupportsAutomaticGraphicsSwitching true. URL types and document types
     are added by T-0006 — leave a `<!-- T-0006 -->` marker comment.
  7. Icon: build `remote-viewer.icns` from `icons/*/virt-viewer.png` with
     `iconutil` (generate the `.iconset` with `sips` for the 128/512/1024
     sizes that are missing — upscale from 256 is acceptable).
  8. `codesign --force --deep --sign - "<app>"` (ad-hoc).
- The script must be re-runnable (wipes and recreates the .app), `set -euo
  pipefail`, `#!/usr/bin/env bash`, runnable from any cwd, and print the
  final app path and size.
- Add a `run_target('macos-bundle', command: [...make-bundle.sh])` ONLY if it
  can be done in `build-aux/macos/meson.build` without touching top-level
  meson.build; otherwise skip (top-level meson.build is out of scope).
- Sandbox note: you cannot `open` the app or talk to WindowServer. Verify
  with `"<app>/Contents/MacOS/remote-viewer" --version` and `otool -L`.
  GUI launch is verified by the QA ticket T-0009.

## Acceptance criteria
- [ ] `bash build-aux/macos/check.sh && bash build-aux/macos/make-bundle.sh`
      exits 0 and produces `build/Remote Viewer.app`.
- [ ] `"build/Remote Viewer.app/Contents/MacOS/remote-viewer" --version`
      prints `remote-viewer version 11.0` (paste in the report).
- [ ] `find "build/Remote Viewer.app" \( -name '*.dylib' -o -name '*.so' -o -path '*/MacOS/*' \) -type f -exec otool -L {} + | grep -E '/opt/homebrew|/usr/local'`
      prints nothing (paste the command + empty result).
- [ ] `codesign --verify --deep --strict "build/Remote Viewer.app"` exits 0.
- [ ] `plutil -lint "build/Remote Viewer.app/Contents/Info.plist"` says OK.
- [ ] Bundle size < 150 MB (`du -sh`, paste it).
- [ ] `docs/macos.md` "Packaging" section replaced with real instructions:
      how to run the script, what is bundled, what is not (GStreamer/audio,
      oVirt), the launcher rationale, and how to ad-hoc vs Developer-ID sign.
- [ ] `.gitignore` ignores `*.app` under build dirs if not already covered.
- [ ] `bash .tigerteam/scripts/run-tests.sh` exits 0.
- [ ] No files changed outside scope.
