## Goal
Milestone 2, step 1 of the native macOS SPICE viewer: consume the SPICE
cursor channel so the local pointer takes the guest cursor's shape (with
correct hotspot), disappears when the guest hides it, and reverts to the
system arrow outside the view. Today a local arrow floats over a guest
that draws its own cursor only sometimes — this is the highest-value ~150
LoC in the gap list (T-0022 report).

## Context
- Read `macos-native/README.md` first; T-0022's report is in
  `.tigerteam/board/done/T-0022.md`.
- API reference: unpacked spice-gtk 0.42 source at
  `/private/tmp/claude-501/-Users-d-b-virt-viewer/48736c42-ecf1-4803-a3b8-b5738f424da3/scratchpad/spice-gtk-0.42/`
  — see `src/channel-cursor.h` / `channel-cursor.c` for `SpiceCursorChannel`
  (the `cursor` property of type `SpiceCursorShape` + its notify, and the
  `cursor-move` / `cursor-hide` / `cursor-reset` signals). Check what 0.42
  actually emits rather than trusting docs; spice-gtk's own
  `src/spice-widget.c` cursor handling is the working example.
- Locked interface (PM decision) — extend `VsmSpiceCallbacks` in
  `vsm-spice.h`, all delivered on the AppKit main thread like the others:
  - `void (*cursor_define)(void *user, int width, int height, int hot_x,
    int hot_y, const uint8_t *rgba)` — @rgba is a malloc'd copy owned by
    the callee (the channel owns the original; copy on the GLib thread).
  - `void (*cursor_hide)(void *user)`
  - `void (*cursor_reset)(void *user)` — revert to the default system arrow.
- Wire the cursor channel in the existing `channel-new` handler in
  `vsm-spice.c` (same pattern as display/inputs); connect it, don't leave
  it dangling.
- `main.m`: build an `NSCursor` from the RGBA bytes (`NSBitmapImageRep` →
  `NSImage` with the hotspot). Treat the shape as 1x points (document the
  choice in the README — a Retina-aware cursor is out of scope). Apply it
  only while the pointer is over the view: `resetCursorRects` /
  `addCursorRect:cursor:` (or a tracking-area `cursorUpdate:`), so the
  cursor is the system arrow over the title bar and outside the window.
  "Hide" = a transparent 1x1 cursor image via the same mechanism — NEVER
  `[NSCursor hide]` (it is app-global and leaks hidden state on focus loss).
- Free/replace the previous cursor on each define; no leak per define
  (thousands arrive over a session).
- Test target: `spice://100.101.77.113:5900` — the user's disposable
  Omarchy (Hyprland) VM. Care rules: benign input only, no
  power-management or destructive key sequences, never hardcode the URI in
  committed code. The guest DPMS-blanks after ~5 s idle; send a benign key
  (arrow) first to wake it. Moving the pointer over different guest UI
  (terminal text area vs desktop) should yield different shapes (I-beam vs
  arrow).
- Engine ceiling ≈45 min wall: commit early and often on your branch; hand
  off INCOMPLETE with precise next steps rather than pushing through.

### For the reviewer
- **Read criterion 3 first.** The synthetic self-test is a substitute for a
  guest shape, not a guest shape. If a target that uses the SPICE cursor
  plane becomes available (a Linux guest on X11/QXL, or any Windows guest),
  the same run with `VSM_TRACE=1` should log real `cursor-define` lines with
  no code change; that is worth one re-run before this is called done.
- The `notify::cursor` handler takes a boxed deep copy from
  `g_object_get()`, then makes a second `malloc` copy for the main thread.
  That is one copy more than the deprecated `cursor-set` signal would need,
  and it is deliberate: the ticket locked the non-deprecated property, and a
  cursor is at most tens of KB.
- `refreshCursorRects` force-sets the cursor only when the window is key
  (commit `aac1f5d`). Without that guard,
  `mouseLocationOutsideOfEventStream` — which reports the pointer in *this*
  window's coordinates whether or not this window is under it — would let an
  occluded viewer repaint the pointer over another app.
- The debug hooks in `vsm-debug.m` (`VSM_CURSOR_SELFTEST`,
  `VSM_CURSOR_CHURN`) are beyond the literal ticket text. They follow the
  existing `vsm_run_input_selftest` precedent and were the only way to
  produce criteria 3/5/6 on a guest that sends no shapes; flagging them
  explicitly in case the reviewer wants them out.
- Out-of-scope things noticed and **not** touched: `cursor-move` is ignored
  (only meaningful in server/relative mouse mode — T-0027); a Retina 2x
  cursor is explicitly out of scope and documented as such; the cursor
  channel is connected for display 0 only, matching the display-channel
  policy, which will need revisiting for multi-display.
- Tooling note for whoever debugs this next: `MallocStackLogging=1`
  **segfaults** this binary — the stack walker walks spice-gtk's coroutine
  stacks (`__thread_stack_pcs` → `stack_logging_lite_malloc` →
  `spice_session_channel_open_host`). Plain `leaks <pid>` works fine. This
  is a tool/spice-gtk incompatibility, not a defect in this code.
- Live-target care: only benign input was sent (arrows, Escape, motion, and
  the pre-existing self-test's clicks/scroll). No power or destructive key
  sequences; the URI is not present in any committed file.
