## Goal
When the binary runs from inside a macOS `.app` bundle, find translations
and data relative to the bundle instead of the compile-time prefix, so the
`.app` is relocatable. Outside a bundle (plain `build/src/remote-viewer` or a
`/opt/homebrew` install) behaviour is unchanged.

## Context
- `src/virt-viewer-util.c` `virt_viewer_util_init()` (~line 266): Windows
  branch derives the locale dir from the module path; the `#else` branch uses
  the baked-in `LOCALE_DIR`. Add an `#elif defined(__APPLE__)` branch.
- Decision (PM): use **CoreFoundation, C only** — no Objective-C:
  `CFBundleGetMainBundle()` + `CFBundleCopyResourcesDirectoryURL()` +
  `CFURLGetFileSystemRepresentation()`. Treat "not in a bundle" as: the
  resources dir path does not end in `.app/Contents/Resources` (CF returns a
  bundle for any executable; the check is the path shape). Fall back to
  `LOCALE_DIR` in that case.
- Add a public helper `gchar *virt_viewer_util_get_bundle_resources_dir(void)`
  declared in `virt-viewer-util.h` (returns NULL when not in a bundle;
  caller frees). `virt_viewer_util_init` uses it for
  `bindtextdomain(GETTEXT_PACKAGE, "<res>/share/locale")`.
- Also in `virt_viewer_util_init`, when in a bundle: if `XDG_DATA_DIRS` is
  unset, `g_setenv("XDG_DATA_DIRS", "<res>/share", FALSE)` so icon themes and
  the mime database inside the bundle are found; likewise
  `GSETTINGS_SCHEMA_DIR` → `<res>/share/glib-2.0/schemas` (only if unset).
  This must happen before `gtk_init` — check call order in
  `src/remote-viewer-main.c` / `src/virt-viewer-main.c` and note it in the
  report if init order needs changing (do NOT change those files; block
  with a question instead).
- Linking: in `src/meson.build` add, gated on
  `host_machine.system() == 'darwin'`, a dependency
  `dependency('appleframeworks', modules: ['CoreFoundation'])` to `util_deps`.
- Document the behaviour in `docs/macos.md` under a new "Running from a
  bundle" section (create the file if T-0001 has not landed yet; keep the
  section self-contained so a merge is trivial).
