## Goal
Six hardening fixes to the bundle packaging, all from the stress reviews
(T-0012 B2/B3, T-0013 B3/N5/N6, T-0014 NB3). Behavior for the normal happy
path (default `BUILD_DIR=build`, integration enabled) must be unchanged
apart from the plist values.

## Context
`build-aux/macos/make-bundle.sh` builds the relocatable ad-hoc-signed
"Remote Viewer.app"; `Info.plist.in` is its template. You are on the
`macbuild` lane: you can and must run the full script to verify.

## Required changes
1. **APP_DIR safety guard** (T-0012 B3). The script runs `rm -rf "$APP_DIR"`
   (~line 82) on a path from the environment with no validation —
   `APP_DIR=.` deletes the source tree. Before any deletion: refuse unless
   the resolved APP_DIR's basename ends in `.app` AND the path either does
   not exist yet or is a directory containing `Contents/Info.plist` (an
   existing bundle being replaced). On refusal, exit 1 with a one-line
   message stating the rule.
2. **Derive `LSMinimumSystemVersion` from the built binaries** (T-0013 B3).
   `Info.plist.in` hardcodes `12.0`, but the bundled Mach-Os inherit the
   Homebrew builder's deployment target (currently `minos 26.0`), so on
   older macOS LaunchServices allows the launch and dyld aborts with no
   dialog. Read the main executable's minos at bundle time
   (`otool -l ... | awk '/LC_BUILD_VERSION/{f=1} f&&/minos/{print $2;exit}'`)
   and substitute it into the generated plist the same way the script
   substitutes its other template values. Keep a sane fallback (the current
   `12.0`) with a warning if otool yields nothing.
3. **Refuse to bundle when the integration is compiled out** (T-0012 B2).
   The plist unconditionally declares spice/vnc URL schemes and the .vv
   document type, but a `-Dmacos_integration=disabled` build contains no
   open-event handler. Early in the script:
   `grep -q '#define HAVE_GTK_MAC_INTEGRATION 1' "$BUILD_DIR/config.h"` or
   exit 1 with a message naming `-Dmacos_integration=enabled` as the
   requirement (PM decision: refuse, do not strip declarations).
4. **copy_modules empty-directory guard** (T-0013 N5). When the module
   source dir exists but holds no `*.so`, the unexpanded glob makes `cp`
   fail and `set -e` kills the run instead of the intended warn-and-return-1.
   Guard the glob (nullglob-style check or `find`) so an empty dir takes the
   same warn+skip path as a missing dir.
5. **Atomic launcher cache writes** (T-0013 N6). The generated launcher
   rewrites `loaders.cache`/`immodules.cache` with `sed > file` on every
   launch; a second concurrent launch (by design — a URI arriving while
   connected spawns a second copy) can dlopen against a truncated cache.
   In the launcher heredoc: write to `<file>.tmp.$$` then `mv` into place.
6. **`LSHandlerRank` for spice** (T-0014 NB3, PM decision): in
   `Info.plist.in`, add `LSHandlerRank` = `Owner` to the `spice` URL-type
   entry only. `vnc` stays rank-free deliberately — do not touch it.

### For the reviewer
- The APP_DIR guard resolves the path with a new `canonicalize()` before
  judging it, so `.`/`..`/symlinks cannot smuggle a non-`.app` past the
  basename test. A path whose parent does not exist is left unresolved and is
  accepted if its basename ends in `.app` — `mkdir -p` creates it, matching
  the previous behaviour.
- `MINOS` is read from `Contents/MacOS/remote-viewer` (post-install), not from
  `$BUILD_DIR/src/remote-viewer`; on this host both are `26.0`.
- Out of scope, noticed but not touched: `Info.plist.in` still hardcodes
  `CFBundleIdentifier`/`CFBundleName`, and the launcher's per-user cache dir
  is derived from the same identifier by hand in the heredoc — the two would
  drift silently if the identifier ever changes.
- Out of scope: the integration refusal reads `$BUILD_DIR/config.h` directly;
  a stale `config.h` from an older configure would be trusted. Cheap to make
  it a `meson introspect` query if the reviewer prefers.
